# ChronoDesk Runtime Behavior

This document explains how ChronoDesk behaves from process start through shutdown. It complements `architecture.md` by describing the concrete runtime sequence, state transitions, failure handling, and user-visible effects.

## Process entry

`src/ChronoDesk.App/Program.cs` configures Avalonia and starts the classic desktop lifetime. `App.axaml` loads global application resources and `App.axaml.cs` performs application composition after Avalonia initializes.

The process may be started normally or with the internal `--background` argument. Platform startup registrations generated by ChronoDesk use `--background` so the application can start with the desktop session without forcing the main window to remain visible when minimize-to-tray is enabled.

## Composition root

`AppServices` is the explicit composition root. A normal application instance constructs:

- `SafeFileLogger` for local redacted JSONL logs;
- `JsonSettingsStore` for local JSON settings;
- `SystemTimeZoneCatalog` for OS timezone discovery;
- `PlatformStartupManager` for user-scoped login startup;
- `SystemChimePlayer` for best-effort local sound playback;
- `ClockFormatter` for display snapshots;
- `ChimePolicy` for cadence, quiet-hour, and duplicate-chime decisions.

The application intentionally does not use a dependency-injection framework. Tests can provide the same dependencies explicitly through the alternate `AppServices` constructor.

## Application initialization

When Avalonia reports framework initialization complete:

1. `App` creates `MainWindowViewModel`.
2. `App` creates `MainWindow` with that view model.
3. `App` subscribes to `SettingsChanged` so theme resources are reapplied when settings change.
4. `MainWindow` becomes the desktop lifetime's main window.
5. `App` attempts to create a tray icon and tray menu.
6. Tray initialization failure is logged and does not prevent the clock from running.

The tray menu exposes Show, Focus, Mini, and Quit actions. Quit explicitly allows the main window to close before shutting down the desktop lifetime.

## Main-window opening sequence

`MainWindow` subscribes to its `Opened` event and owns a 250 ms `DispatcherTimer`.

On first opening:

1. `MainWindowViewModel.InitializeAsync` loads settings.
2. Settings are normalized by the persistence/domain layer.
3. World-clock card view models are rebuilt.
4. The timezone search list is initialized.
5. An immediate clock tick populates visible clock fields.
6. `SettingsChanged` is raised so the application theme and window behavior are synchronized.
7. The 250 ms UI timer starts.
8. If `IsFirstRun` is true, onboarding is shown modally.
9. If the process contains `--background` and `MinimizeToTray` is enabled, the main window hides after initialization.

If local settings initialization fails with an I/O or access error, the view model logs a safe event, exposes a warning status, and still marks initialization complete so the application can remain usable with its current in-memory defaults.

## Clock tick model

The UI timer fires every 250 ms. ChronoDesk does not assume every tick will run exactly on schedule; each tick asks the injected `TimeProvider` for a fresh UTC instant.

`MainWindow` protects against overlapping ticks with `tickInProgress`. If one asynchronous tick is still running, the next timer event is skipped rather than starting a second refresh concurrently.

Each successful `TickAsync` performs these operations:

1. Read current UTC time from `TimeProvider`.
2. Build the local-clock snapshot through `ClockFormatter` using `TimeZoneInfo.Local`.
3. Update time, date, weekday, ISO week, calendar details, and timezone display fields.
4. Update every world-clock card using the same instant so all cards represent one coherent moment.
5. Ask `ChimePolicy` whether a chime should occur.
6. If allowed, record the chime instant before playback and invoke `IChimePlayer`.
7. Convert optional chime playback failure into a safe status/log event rather than crashing the timer.

A timer-level exception is also contained and logged by `MainWindow`; one failed refresh does not automatically stop future ticks.

## Clock formatting

`ClockFormatter` is deterministic for a supplied instant, timezone, settings snapshot, and culture.

It supports:

- 12-hour or 24-hour time;
- optional seconds;
- locale-aware short date;
- locale-aware weekday;
- ISO week number;
- optional day-of-year, ISO week, and UTC-offset detail line;
- standard/daylight timezone display name chosen from the target timezone at the converted instant.

ChronoDesk converts the UTC instant with `TimeZoneInfo.ConvertTime`. It does not calculate civil-time offsets manually.

## World clocks

Persisted world clocks are domain models containing an ID, display name, and timezone ID. `AppSettings.Normalize` removes malformed entries, de-duplicates IDs, limits the collection to 24, and guarantees at least one valid entry.

At runtime, `SystemTimeZoneCatalog.Resolve` tries the stored ID directly and then attempts .NET IANA/Windows ID conversion in both directions. If the timezone still cannot be resolved on the current operating system, UTC is returned as a safe fallback.

Adding a world clock:

- refuses a second card for the same timezone ID, ignoring case;
- uses the timezone display name unless the caller supplies a nonblank label;
- persists through the normal settings update transaction.

Removing a world clock:

- refuses to remove the final remaining clock;
- persists through the same settings update path.

## Settings transaction semantics

`MainWindowViewModel.UpdateSettingsAsync` is the central settings transaction.

The sequence is deliberate:

1. Normalize the candidate settings.
2. Detect whether `StartWithSystem` changed.
3. If supported and changed, apply the requested platform startup state.
4. Persist the normalized settings.
5. If persistence fails after startup was changed, attempt to roll startup back to its previous state.
6. Only after persistence succeeds, replace the live `Settings` snapshot.
7. Rebuild world-clock cards.
8. Refresh the clock immediately.
9. Raise `SettingsChanged`.

This ordering avoids telling the UI that a setting succeeded before durable persistence succeeds. Startup rollback failure is logged separately because the application cannot guarantee the external OS registration and JSON file remain synchronized after a second failure.

## Settings window behavior

`SettingsWindow` loads controls from the current normalized settings snapshot.

Save behavior:

- quiet-hour inputs must parse as `HH:mm` or another invariant-culture `TimeOnly` form;
- invalid quiet-hour text prevents persistence and startup changes;
- selected controls are converted into a new immutable `AppSettings` snapshot;
- the view model transaction performs normalization, startup integration, persistence, refresh, and notifications;
- successful save closes the window;
- expected I/O/access/invalid-operation failures remain in the dialog and show a localized status.

Reset behavior creates fresh defaults with onboarding already completed, applies them through the same transaction, reloads controls, and leaves the Settings dialog open with a success status.

## Import and export

Export writes the current normalized settings snapshot to a user-selected JSON file.

Import intentionally does **not** allow an imported file to silently enable or disable login startup. After an imported settings document is validated, ChronoDesk forces:

- `IsFirstRun = false`;
- `StartWithSystem` to the current local value.

The resulting safe snapshot then passes through the ordinary update transaction.

Native file pickers are supplied by Avalonia/the host platform. The persistence layer beneath them is independently testable and does not depend on the picker implementation.

## Focus mode

Focus mode is ephemeral window state; it is not persisted.

Entering focus mode:

- exits mini mode first if needed;
- hides header, world clocks, quick-add area, and footer;
- enters full screen;
- increases the hero-card minimum height.

Exiting restores normal window state and application chrome.

Keyboard behavior:

- `F11` toggles focus mode;
- `Esc` exits focus mode.

## Mini mode

Mini mode is also ephemeral.

Before entering, ChronoDesk records normal width, height, position, and topmost state. It then:

- exits focus mode if active;
- reduces minimum and current dimensions;
- forces always-on-top;
- uses border-only system decorations;
- hides application chrome;
- keeps the clock card visible.

On exit, dimensions and remembered position are restored. The final topmost state respects both the persisted `AlwaysOnTop` preference and the pre-mini state.

Keyboard behavior:

- `Ctrl+M` toggles mini mode;
- `Esc` exits mini mode.

## Other keyboard shortcuts

- `Ctrl+K` focuses timezone search.
- `Ctrl+,` opens Settings.
- `Ctrl+Shift+T` toggles the persisted normal always-on-top preference.

Shortcuts are handled by `MainWindow`; they are not global OS hotkeys.

## Close, tray, and shutdown behavior

When the user closes the main window:

- if `MinimizeToTray` is enabled and shutdown was not explicitly requested, closing is cancelled and the window hides;
- otherwise the clock timer stops and the window can close.

Tray **Show** restores a hidden/minimized window and activates it.

Tray **Quit** calls `AllowClose`, stops the timer, and then requests desktop lifetime shutdown.

Tray functionality is best-effort. If tray initialization is unavailable, the main clock remains functional, but platform behavior must be validated on real desktop environments before release claims are made.

## Theme behavior

`App` reacts to settings changes and applies one of these effective modes:

- system/default;
- light;
- dark;
- high contrast.

`HighContrast` is honored if either the dedicated boolean preference is true or the theme enum itself is `HighContrast`.

ChronoDesk updates named dynamic brush resources rather than rebuilding every view manually. High contrast uses a dedicated palette; light and dark use their corresponding ChronoDesk palette values.

## Chime behavior

Chimes are disabled by default.

`ChimePolicy` requires all of the following:

- chimes enabled;
- current local time outside configured quiet hours;
- exact interval boundary with `Second == 0`;
- no prior chime in the same local calendar minute.

Supported intervals are hourly, half-hourly, and quarter-hourly.

The duplicate guard compares local year/day/hour/minute so repeated timer ticks within the same boundary minute do not replay the sound.

## Error containment philosophy

Optional facilities must not take down the clock. Current examples include:

- tray initialization failure;
- chime helper absence or playback failure;
- log-write failure;
- unavailable persisted timezone;
- malformed/corrupt settings loading;
- unsupported startup integration.

Operations that represent explicit user changes, such as saving settings, still surface failure instead of silently claiming success.

## Network behavior

Normal clock, timezone, settings, tray, startup, and chime behavior does not require network access.

ChronoDesk only hands an external HTTPS/mailto URI to the OS after a deliberate user action in Settings or About. The application does not perform background release polling, telemetry, sign-in, analytics, cloud sync, or automatic package downloading.

## Shutdown and disposal

The tray icon is disposed when the classic desktop lifetime exits. `MainWindow.AllowClose` stops the clock timer before explicit tray Quit shutdown. Other short-lived resources such as external chime processes are disposed after use.

## Runtime behavior changes checklist

When changing runtime behavior, update at least:

- the relevant source/tests;
- this document when lifecycle or state transitions change;
- `architecture.md` if dependency boundaries change;
- `settings-reference.md` for persistent behavior changes;
- `platform-integration.md` for OS-specific behavior changes;
- `PRIVACY.md` or `SECURITY.md` when trust/data boundaries change;
- `CHANGELOG.md` for user-visible changes;
- `repository-reference.md` if tracked files are added, renamed, or removed.
