## Phase 8 work completed in source

### Linux XDG autostart generation hardened

Previously, `PlatformStartupManager` contained a minimal inline Linux `Exec` quoting helper that only escaped backslashes and double quotes. Freedesktop desktop-entry `Exec` parsing has additional escaping and field-code semantics that need special handling.

The new internal `LinuxDesktopEntry` formatter now:

- always serializes the executable as one quoted `Exec` token;
- applies the required double-backslash layer for double quotes, dollar signs, and backticks inside a quoted `Exec` argument;
- applies the required four-backslash representation for literal backslashes inside the quoted token;
- doubles `%` as `%%` so a literal percent cannot be interpreted as a desktop-entry field code;
- rejects executable paths containing `=`, CR, or LF because those forms cannot be represented safely as the executable token in the desktop-entry `Exec` grammar;
- keeps `--background` as an explicit argument rather than concatenating it into the executable token.

`PlatformStartupManager` now delegates Linux desktop-entry serialization to this formatter and retains responsibility for the XDG autostart path and file lifecycle.

### macOS LaunchAgent generation isolated and tested

The macOS LaunchAgent XML previously lived inline inside `PlatformStartupManager`. It is now generated by `MacLaunchAgentPlist` so XML serialization can be tested without mutating a real `~/Library/LaunchAgents` directory.

The formatter:

- XML-escapes the executable path;
- preserves the executable as its own `ProgramArguments` element;
- includes `--background` as a separate argument;
- keeps the stable `com.sanskar.chronodesk` label;
- keeps `RunAtLoad` enabled.

### Deterministic platform-artifact tests added

`ChronoDesk.Infrastructure` now grants `ChronoDesk.Tests` internal visibility only for test access to the serialization helpers.

New regression tests cover:

- Linux paths containing spaces;
- Linux `$`, backtick, `%`, backslash, and double-quote escaping;
- rejection of Linux executable path forms containing `=`, CR, or LF;
- macOS plist XML parsing;
- preservation of macOS executable paths containing XML-sensitive characters;
- presence of `--background`, `RunAtLoad`, and the expected LaunchAgent label.

These tests improve deterministic cross-platform coverage without pretending to replace native startup enable/disable testing.

### Release CPU-architecture coverage expanded

The tagged release workflow previously generated four self-contained ZIP targets:

- `win-x64`
- `linux-x64`
- `osx-x64`
- `osx-arm64`

Phase 8 expands the matrix to six targets:

- `win-x64`
- `win-arm64`
- `linux-x64`
- `linux-arm64`
- `osx-x64`
- `osx-arm64`

The existing exact tag/version verification, self-contained single-file publishing, bundled release documentation, artifact upload, checksum generation, and GitHub Release publication remain intact.

The new ARM64 packages are advertised as release targets, but native launch validation on matching hardware remains a release gate before `v2.6.0.2` is tagged.
